# Проверки перед выпуском

CI и Deploy production используют одну локальную action `.github/actions/verify`.
До установки файлов она запускает:

1. `mvn clean verify`: существующие тесты движка и приватности, полный Spring Boot
   на случайном HTTP-порту, публичные маршруты, создание/подключение/чтение состояния,
   отказы 401/404 и проверку обязательного admin token.
2. Тесты скрипта HTTP readiness: 502, HTML вместо JSON, неверный backend, ошибка
   отдельного публичного маршрута, восстановление после старта и постоянная недоступность.
3. `npm ci` и `npm run check`: `no-undef` для исходников, регрессия лишнего `г`,
   сборка Vite. Обычный `npm run lint` остаётся более широким ручным аудитом.
4. Playwright Chromium с собранным frontend и настоящим Java JAR: создание игры,
   подключение, добавление бота, старт, отображение ActionBoard и восстановление
   после перезагрузки. Необработанные JS-ошибки и ответы 5xx проваливают этот сценарий.
   Отдельный сценарий подменяет только create-запрос ответом 502 и проверяет,
   что стартовая страница остаётся доступной после сообщения об ошибке.

Backend HTTP-тест использует временные SQLite и каталоги. Браузерный запуск также
создаёт временные данные и тестовый token, закрывает Java и удаляет данные по завершении.
Тесты не используют production token, базу или учётную запись. Браузер работает
с портами 18081 (Java) и 14173 (preview); они должны быть свободны. Уже запущенный
сервер не переиспользуется. Запускайте один такой набор на runner одновременно.

## Локальный запуск

Нужны JDK 21, Maven и Node 22. Из корня репозитория:

```sh
mvn -f politikum-main-backend/pom.xml clean verify
node --test scripts/check-http.test.mjs
cd politikum-main-frontend
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
```

На Linux Chromium требует системные библиотеки: CI устанавливает их командой
`npx playwright install --with-deps chromium`. Self-hosted runner должен иметь
доступ к загрузкам и права установки этих пакетов. При ошибке установки выпуск
останавливается до замены файлов приложения. Диагностика неудачных тестов
сохраняется в GitHub Actions artifacts на 7 дней.

## После деплоя

`systemctl is-active` дополнен чтением `/games/politikum`, `/public/news`,
`/public/lobby_chat`, `/public/matches_open`. Проверяются HTTP 200, JSON и `ok: true`,
а для health также `backend: java` и `liveMatches: true`.
Требуются три успешных прохода подряд с интервалом 2 секунды. На ожидание каждого
адреса отведено 90 секунд; отдельный HTTP-запрос ограничен 5 секундами.

Сначала проверяется Java напрямую, затем nginx с production Host:

```sh
PROBE_HOST=109.107.167.179 node scripts/check-http.mjs http://127.0.0.1:8081 http://127.0.0.1
```

Этот шаг должен выполняться **на сервере**, где находятся nginx и Java.
Он ничего не записывает: создание игр проверяется до установки в изолированной среде.
Он проверяет локальный маршрут через nginx, но не внешнюю сетевую доступность IP.
Ошибка завершает deployment красным статусом; автоматического отката здесь нет.
Production по-прежнему требует корректный `POLITIKUM_ADMIN_TOKEN` в конфигурации
systemd (в текущей установке `/etc/politikum/backend.env`), длиной не менее 16 символов.
Тестовый token никогда не устанавливается в production.

У deployment отключена отмена текущего запуска новым push, чтобы не прерывать
копирование файлов или перезапуск. Эти проверки ловят известные регрессии старта
и первого открытия игры; они не покрывают все игровые механики и будущие сбои сервера.
